Exercise 1 — Workspace Initialization & Data Dictionary

Initialize the workspace, generate the data dictionary from BANKDATA, and set the documentation output folder.

Step 1 — Initialize the workspace

🧰 Z Code mode — new task
/init and create the local metadata database with the scan_program tool.
Output:
· .bobz/local-settings.json — metadata DB, 29 COBOL programs scanned
· AGENTS.md — created at workspace root
⚠️ If Bob asks whether to focus on COBOL or Assembler, choose COBOL.

Step 2 — Generate the data dictionary

Click the workflow button (▶) → Generate data dictionary → select BANKDATA.cbl. Review the dictionary, then click "I am done editing" to save.

Output:
· bobz/DD.json — data dictionary with 15 documented business entries from BANKDATA
⚠️ If AGENTS.md is not updated by the workflow, ask: verify if @AGENTS.md is up to date with data dictionary?

Step 3 — Update AGENTS.md with the output folder

Update @AGENTS.md to specify that all generated documentation, reports, and diagrams must be saved under the docs/ folder.
Output:
· AGENTS.md — updated with the docs/ convention for all future conversations
🎓 What You Learn
  • The importance of initialization: Metadata (.bobz/local-settings.json) and the data dictionary (bobz/DD.json) are the foundation for all quality analyses.
  • Time savings: Instead of 2–3 days of manual exploration, Bob analyzes everything in minutes.
  • Standardization: Naming and output conventions are automatically established.
  • Living documentation: AGENTS.md serves as a persistent reference across all conversations.

· .bob/skills/cbsa-coding-standards/SKILL.md — patterns, checklist, and sample code
🎓 What You Learn
  • Automated inventory: Bob uses execute_sql_query against the metadata database to extract a full structured inventory in minutes vs. days manually.
  • Coding standards as a skill: Extracting patterns into a reusable SKILL.md means Bob can apply them consistently in every future task.
  • Verification workflow: After creating the skill, reload the workspace (File → Close Folder then reopen) so Bob detects the new skill file before testing it.

🧰 Z Code mode — new task
extract the business rules from @BNK1CAC.cbl and save them to a markdown file
Output:
· docs/BNK1CAC-business-rules.md — all current input validation rules listed as reference

Step 2 — Add the new validation rule

@BNK1CAC.cbl add an input validation rule to verify that a customer number starts with 99, then update the documentation to reflect this change
Output:
· BNK1CAC.cbl — updated with the IF CUSTNOI(1:2) NOT = '99' validation block
· documentation updated to reflect the new rule

Step 3 — Fix the missing copybook

In the PROBLEMS panel, right-click the "Unable to find copybook BNK1CAM" error → Fix with Bob → accept the prompt.

Output:
· BNK1CAM.cpy — recreated from the BMS definition

Step 4 — Generate an enhancement report

Create a markdown formatted report on all of the possible enhancements that could be made on @BNK1CAC.cbl
Output:
· docs/BNK1CAC-enhancement.md — identifying bugs (e.g., move to ABND-TIME) and duplicated lines
🎓 What You Learn
  • Business rule extraction: Bob identifies implicit rules not visible in specs — only in code.
  • Inline code generation: Right-click → IBM Bob → Add to Context lets you target a precise line and generate code in place.
  • Copybook recovery: Bob can recreate missing copybooks from BMS definitions when compiler errors appear in the PROBLEMS panel.
  • Enhancement analysis: Bob identifies bugs and improvement opportunities across the full program.

Output:
· a summary of every location where SORTCODE appears — which programs reference it, in which paragraphs, and whether it originates from a copybook or is defined locally

Step 2 — Run the full impact analysis

Analyze the impact of changing SORTCODE to support multiple bank branches.
Output: docs/CBSA-archi-impact***.md — impact report covering:
· which programs directly reference SORTCODE
· which copybooks propagate it and downstream programs affected
· estimated effort, risk rating, and DB2 migration plan
· mitigation strategies
Bob uses execute_sql_query against the metadata database built in Exercise 1 — turning what would normally be a multi-day manual audit into a few minutes of conversation.
🎓 What You Learn
  • Cross-application tracing: Bob queries the metadata database with execute_sql_query to find every SORTCODE reference in seconds.
  • Risk-rated impact reports: Output covers impacted programs, copybooks, DB2 tables, estimated effort, risk rating, and mitigation strategies.
  • AI-assisted planning: What would normally be a multi-day manual audit becomes a few minutes of conversation.
